# common-safe-implementation

実装に入る **前** に使うSkill。いきなりコードを書かず、まず安全確認の成果物を出す。

## このSkillがやること

- 変更対象と影響範囲を明確にする
- 触ってはいけない領域を先に宣言する
- 危険操作・外部送信・不明点を洗い出す
- 「提案 → 承認 → 実行」の順番を守らせる

## このSkillがやらないこと

- コードの自動変更
- 破壊的コマンドの実行
- `.env` / 認証情報の作成・編集
- `git push`

## 手順

1. 目的を一文で要約する
2. 変更対象ファイルを列挙する（新規 / 既存編集を区別）
3. 触ってはいけない領域を明示する（認証・課金・本番DB・既存ノート等）
4. 変更案を箇条書きで出す
5. 影響範囲とリスクを評価する
6. 不明点を列挙し、推測で埋めない
7. 承認を得てから実装に進む

## 出力フォーマット

```md
## 実装前チェック：〇〇

### 目的
- （一文で）

### 変更対象
- 新規：path/to/file
- 既存編集：path/to/file（理由）

### 触らない領域
- 認証 / 課金 / 本番DB / 既存ノート / 旅行切替 …

### 変更案
1.
2.

### 影響範囲・リスク
- 取り返しのつきにくさ：低 / 中 / 高
- 外部送信・公開：あり / なし

### 不明点（要確認）
-

### 進め方
- 承認後、最小単位で実装 → 動作確認 → 報告
```

## 安全チェック（必須）

- [ ] 破壊的操作（削除・一括上書き・force push）を含まない
- [ ] 認証情報・課金・本番DBに触れない
- [ ] 既存ファイルを勝手に削除・改変しない
- [ ] 不明点を推測で埋めていない
