# common-code-review

変更差分を **レビューする** Skill。自動で直さず、観点と指摘を出す。

## このSkillがやること

- diffを読み、リスクの高い箇所を指摘する
- バグ・安全性・整合性・可読性の観点を出す
- テスト・確認の漏れを洗い出す

## このSkillがやらないこと

- 勝手なコード修正（指摘までに留める）
- `git push` / コミットの自動実行

## レビュー観点チェックリスト

### 正しさ
- [ ] 仕様どおりの挙動になっているか
- [ ] 境界値・null・空・エラー時の扱いは妥当か
- [ ] 既存の挙動を壊していないか（回帰）

### 安全性
- [ ] 認証情報・課金・本番DBに影響していないか
- [ ] 破壊的操作・不可逆な変更が混ざっていないか
- [ ] 外部送信・公開につながる変更はないか

### 整合性
- [ ] 単一ソースであるべき定数を二重定義していないか
- [ ] 似た処理の重複・コピペがないか
- [ ] 命名・スタイルが周囲のコードと揃っているか

### 可読性・保守性
- [ ] 過剰に複雑になっていないか
- [ ] 不要なコメント・デッドコードが残っていないか

### テスト・確認
- [ ] 動作確認の手順が明確か
- [ ] テストが必要な変更にテストがあるか

## 出力フォーマット

```md
## レビュー：〇〇

### 概要
- 変更の要点（1〜3行）

### 指摘（重要度順）
1. [高] 〇〇：理由 / 提案
2. [中] 〇〇：理由 / 提案
3. [低] 〇〇：理由 / 提案

### 良かった点
-

### 確認すべきこと
- 
```

## 手順

1. 対象の差分を確認する（範囲を明確化）
2. 上のチェックリストで観点を回す
3. 重要度（高/中/低）を付けて指摘する
4. 自動修正はせず、提案として出す
