# E-NEXUS共通 収益シミュレーション（revenue-sim）

サブスクの価格・AI利用枠・事業者の原価・為替・ストア手数料・紹介報酬を変えて、利用者1人あたりの収益と利益を再計算する仕組み。
旅レートカメラのPro+で使い始めたが、**エンジンはアプリに依存しない**。アプリごとの値はシナリオ（JSON）にだけ置く。

- 通信しない・有料APIを呼ばない。依存なし（Node 24の標準だけ）
- **このrepoは公開repo**。実際のアプリの価格候補・報酬条件・利益率のシナリオとレポートは、ここに置かず非公開の置き場（Vault）に置く。
  ここにあるのは計算式・テスト・中立な例（`apps/example/scenario.json`）だけ

## 使い方

```bash
npm run revenue-sim -- check --scenario <scenario.json>
npm run revenue-sim -- run   --scenario <scenario.json> [--out <dir>] [--set fx=190 --set plans.monthly.price=1280]
npm run test:revenue-sim
```

`run` は `<app>-revenue-<asOf>.md`（Humanが読む表）と `.json`（全ての数字）を出す。`--set` は値の一時的な上書き（JSONで書く）。

## 用語（混同しないための定義。`engine/model.mjs` の冒頭と同じ）

| 用語 | 定義 |
|---|---|
| 売上（gross） | 税込の販売価格。Apple日本の手数料は「ユーザーが支払う価格」に掛かる |
| 受取（proceeds） | 税と手数料を引いた後。**税を引くのは `proceedsOf` の1か所だけ**（`tax.mode`：本則で控除可／控除不可／現金） |
| 変動費 | AI音声・AIテキスト・サーバー・返金・RevenueCat・無料体験（利用者ごとに増える） |
| 貢献利益 | 受取 − 変動費（紹介報酬の前） |
| 紹介報酬 | 方式（初回のみ／初年度のみ／継続）×基準（貢献利益／契約の固定控除／受取）×率 |
| 報酬控除後 | 貢献利益 − 紹介報酬。「受取比」はこれ÷受取 |
| 固定費 | 契約者数の段で決まる月額。貢献利益に混ぜず、損益分岐で使う |

## 計算の要点

- 年額は1回の課金で12か月分のAI枠を持つ（毎月更新）。原価は12倍、月換算は1/12
- ストア手数料は「同じ購読で有料1年を超えたか」で変わる（日本：1年目以降の自動更新サブスクは10%＋5%）
- 音声：請求の分数＝利用者の枠×`billedPerUserMinute`＋セッションごとの付加分＋異常終了のリース。
  中継の**原価上限**（`costCapUsdPerMonth`）は「中継が報告した原価」で止める。報告の作り（`costReport.basis`）は
  `per_user_minute`（利用者の枠1分あたり一律の額。事業者の単価に関係なく同じ分で止まり、値上げ・無音の課金からは守らない）と
  `provider`（事業者の実原価。上限が実費の天井）の2通り。実費は提供した分の請求×事業者の単価×安全係数。
  上限が先に効くと宣伝した分数を提供できない（レポートの⚠。利益ではなく商品の問題として出す）
- テキスト：1回の上限トークン×単価×回数
- 紹介報酬の方式は en-partner-hub の `payout_months`（支払対象の月数）に対応する：初回のみ＝1回目の課金だけ、初年度のみ＝有料12か月、
  継続＝上限なし（hub は整数が必須なので長い月数）。年額では「初回のみ」＝「初年度のみ」
- 紹介報酬の基準は2つを併記する：**貢献基準**（実際の貢献利益）と**契約基準**（hub の式：税込−税の割合→手数料率の順で推定手取り、
  そこから契約で合意した固定の控除×カバー月数）。hub は利用者ごとの実原価を持たないので、高利用の紹介利用者では契約基準が多く払う
- 回帰：アプリ固有の旧試算との一致は、非公開の置き場にある回帰スクリプトで確かめる（公開repoのテストは中立な値だけ）

## シナリオの書き方

数値の葉は `{"value": x, "status": "confirmed|measured|estimate|assumption|unverified", "source": "出所"}`。
`check` は status・source の欠け、値域、存在しない選択を拒否する。必須の構成は `apps/example/scenario.json` を見る。
`analysis` に比べる価格・枠・事業者・為替・手数料・紹介の率と方式・ストレスケース（`set` で値を上書き）を書く。

## 他のアプリで使う

`apps/example/scenario.json` を写して、非公開の置き場で値を変える。式を変える必要があれば `engine/model.mjs` を直し、テストを足す。
