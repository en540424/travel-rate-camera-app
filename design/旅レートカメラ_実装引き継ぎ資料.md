# 旅レートカメラ UI実装引き継ぎ資料

> 本資料は Claude Design で作成した「無料版MVP」＋「最小Pro版」の全画面を、Claude Code / Cursor / 実装AI へ渡すための引き継ぎドキュメントです。
> **新規画面の追加は不要。** 既存デザインを React Native / Expo / TypeScript / expo-router で実装するための仕様・トークン・順序・注意点をまとめています。
> 対象スタック: React Native ・ Expo ・ TypeScript ・ expo-router ・ expo-sqlite ・ expo-camera ・ OCR ・ RevenueCat / StoreKit（ローカル保存中心 / バックエンド最小）。

## 1. アプリ概要

**旅レートカメラ** は、旅行中の商品価格を **カメラOCR / 商品写真 / 手入力** で記録し、**日本円換算・候補管理・購入済み管理・予算管理・履歴・カレンダー・分析** ができるアプリ。

- **主役の体験**: 「撮る → 円で見る → 候補/購入済みに保存 → 履歴・カレンダーで見返す」。分析やProは**主役を邪魔しないサブ機能**。
- **リリース方針**: まず無料版MVPを完成させ、**初回リリース時点で最小Pro版も同梱**。無料版を気に入ったユーザーが自然にProへ移行できる状態を目指す。
- **データ**: ローカル保存中心（expo-sqlite）。クラウドは高性能OCR（将来 Google Vision 系）と課金（RevenueCat/StoreKit）のみ。
- **OCR段階**: ①基本OCR（無料・端末内想定）→ ②高性能OCR（Proの月間回数制・クラウド）→ ③AI OCR（将来機能）。

### コア・ユーザーゴール
1. 値札/メニューを撮って**即・日本円**で把握
2. 迷ったものは**候補（アンバー）**、買ったものは**購入済み（ティール）**に保存
3. **予算の残り**をいつでも確認
4. 旅行後に**履歴・カレンダー・分析**で振り返る

## 3. デザイン方針

- **白ベース**、`color.bg` の淡いウォームグレー上に白カード。
- **ティールが主役**（`color.primary`）。CTA・主要アクション・購入済みステータス。
- **候補＝アンバー系 / 購入済み＝ティール系**（アプリ全体で厳守）。
- **Pro＝上品なゴールド系アクセント**（識別・バッジのみ。CTAはティールのまま）。
- **丸みのあるカードUI**、余白を広く、**数字は大きく**（`fontFeatureSettings: 'tnum'` で等幅）。
- **状態が一目で分かる**（選択側は白＋影、満杯バー、残回数pill など）。
- **写真と日本円換算が主役**。分析・Proは控えめ。
- **押し売りしないPro導線**（上部に大きく出さない／逃げ道を必ず用意）。
- 参照トーンは **Wise / Revolut / Apple 系の信頼感**。ただしコピーではなく旅レートカメラ独自。
- **絵文字は国旗のみ**（通貨表示）。装飾アイコンは線画SVG（stroke 1.8–2.6）。

## 6. 画面別仕様

> 形式: **目的 / 主要UI / 状態**。状態はそのまま実装の表示分岐に対応。

### 6-A. メイン画面 v4
- **目的**: 撮る→円で見る→候補/購入済み保存→次へ、を1画面完結で。**起動時は必ず価格OCRモード**。
- **主要UI**: 上部にモード切替セグメント（価格OCR / 商品写真、タップ主体＋横スワイプ補助、選択側は白＋影）／カメラ枠＋ガイド／撮影ボタン（OCR=ティール、商品写真=チャコール+弱影で区別）／下部に小さな予算サマリー＋手入力サブ導線。
- **結果パネル**（OCR後はカメラを小サムネに退避、結果が主役）: 円換算ヒーロー＋保存後の残予算pill／金額候補チップ／メモチップ／「履歴に残す写真」行（商品写真を撮る/他から、値札タグ）／固定フッターに候補↔購入済みトグル＋保存＋「保存しないで次を撮る →」。
- **状態**: ①撮影前（OCR/写真）②読み取り中（スキャンライン）③OCR成功 ④OCR失敗→手入力（同パネルで金額入力主役＋撮り直す）⑤商品写真から（金額手入力＋後からOCR追加の点線ボタン）⑥保存完了→続けて撮影 ⑦写真変更シート。

### 6-B. 履歴・商品管理
- **履歴**: 目的=保存済みを見返す。主要UI=候補/購入済みフィルタ＋ItemCardリスト。状態=通常/空/旅行未選択。
- **商品詳細**: 写真・金額（円＋現地）・状態・メモ・日時。候補→購入済みの変更導線。編集/削除入口。
- **商品編集**: フォーム（金額・メモ・状態・写真）。**右上キャンセルは廃止**（§10）。左上キャンセル＋中央タイトル＋下部保存。
- **シート**: 写真変更（撮影/ライブラリ/OCR写真/削除）／削除確認（destructive）。

### 6-C. 旅行・レート設定
- **旅行作成**: 名称・通貨・レート・期間・予算。状態=入力/エラー/完了。**フォームは下タブ非表示可**（§10）。
- **レート設定**: 手入力レート＋RatePreviewCard。レート変更確認シート。**保存済み商品は保存時レートを維持**（§10）。
- **通貨選択**: 一覧から選択。
- **旅行一覧 / アクティブ切替シート**: TripCard/TripRow。状態=旅行なし・初回／レート未設定／終了・アーカイブ導線。

### 6-D. カレンダー・設定
- **カレンダー**: 月表示（月サマリー＋日付セル：候補=アンバー/購入済み=ティールのドット＋その日の合計、今日=枠、選択=ティール塗り、凡例常駐）。日付タップで週ストリップ＋当日記録（ItemCard流用）。状態=通常/空/旅行未選択。**セルが狭い時は金額省略・ドット優先**（§10）。
- **設定トップ**: 最上部に現在の旅行カード（黒ヒーロー：残予算・レート・編集/切替）→「旅行とレート/データ/サポート」3セクション→**最下部に控えめPro行**。
- **データ管理**: DataStatCard（保存/旅行/候補/購入済み）＋「この端末に保存」明示＋CSV/PDF（Pro/Pro予定）＋危険な操作（全削除→確認シート）。
- **ヘルプ**: **軽いアコーディオンで十分**（§10）。アプリ情報: 規約/プライバシー/問い合わせ/ライセンス。

### 6-E. 分析（アクティブ旅行が主役・日別は補助）
- **分析トップ**: 上部に旅行切替チップ→`AnalysisSummaryCard`（購入済み/候補合計）→`BudgetProgressCard`（使用率）→`ComparisonCard`（候補購入後の残予算）。
- **日別**: `MiniBarChart`（積み上げ・View製）＋`DaySpendRow`→カレンダー導線。
- **価格帯**: `PriceRangeCard`（固定4バケット）＋最下部`ProHintCard`。
- **状態**: 空（記録ゼロ：カメラ/旅行作成へ）／旅行未選択（旅行作成/既存選択）／データ不足（サマリー・予算は機能、日別は点線プレースホルダ＋アンバー小バナー）。

### 6-F. 最小Pro版
- **Pro紹介**: 黒ヒーロー「旅の記録を、もっと自由に。」＋主要6機能（保存/旅行上限解除・高性能OCR回数制・詳細分析・CSV/PDF・今後追加）＋「プランを見る」。下部に今後追加予定カード。
- **機能一覧**: 無料 vs Pro の比較表＋高性能OCR説明（使い切っても翌月リセット・基本OCR/手入力は無料継続）。
- **料金プラン**: 月額/年額（おすすめ・黒×ゴールド）/買い切り。**高性能OCR=50/100/10回。買い切りにクラウド無制限を含めない**。価格はconfig＝差し替え容易、注記で「仮」。
- **上限到達**: 保存（30/30バー・「保存済みは残る」・あとで）／旅行（複数旅行の価値3チップ・「既存の旅行を使う」）。**責めない・逃げ道必須**。
- **高性能OCR**: 利用前シート（残回数pill・送信の透明性・「手入力する」）／使い切り（リセット日・「手入力で続ける」主・「プランを確認」副）。
- **購入確認**: 選択プラン＋価格＋含まれる機能＋月間OCR回数＋自動更新/解約可/Apple ID請求。
- **購入完了**: ティールチェック＋ゴールド星、解除内容3行、次アクション3つ。
- **購入復元**: 用途明記＋1アクション＋復元不可時ヘルプ。
- **既存画面内Pro導線**: 設定（旅行カードの下）／分析（最下部）／データ管理（CSV/PDFにPro・Pro予定バッジ）。いずれも控えめ。

## 10. 重要修正メモ（実装時に必ず反映）

### 下タブ（最重要）
- Claude Design上では一部画面で下タブのアクティブがカメラになっているが、**実装側で各画面に正しいactiveを割り当てる**:
  - カメラ→カメラ / 換算→換算 / 履歴→履歴 / カレンダー→カレンダー / 分析→分析 / 設定→設定
  - 詳細・編集・作成・Pro・購入画面 → **遷移元タブを維持、または下タブ非表示**
- **下タブを二重に作らない / 下タブの上に別タブUIを足さない / 画面下部に二重タブを作らない**。expo-router の `(tabs)` レイアウトを単一の正とする。

### 商品編集画面
- **右上キャンセルを削除**。左上キャンセル＋中央タイトル＋下部保存ボタンで十分。

### 旅行作成 / 編集系フォーム
- **下タブ非表示でも可**。保存前に別タブへ移動して**入力が消える事故を防ぐ**（離脱確認 or タブ非表示）。

### レート変更
- MVPでは**保存済み商品は保存時レートを維持**。新レートは以後の保存に適用。**候補だけ再計算する案は後回し**。

### カレンダー
- 日付セルが狭い場合、**金額を無理に入れずドット＋選択日の詳細表示を優先**。

### ヘルプ
- **軽いアコーディオンで十分**。詳細ページ・画像付きチュートリアルはMVP不要。

### 分析
- **旅行単位を主役**。日別支出は補助。**月別分析は後回し**。

### 高性能OCR
- 初期は **Google Vision系**を想定。AI OCRは将来。**必ず月間回数制限**。
- **画像はOCR処理のため送信される可能性**→**利用前説明＋プライバシーポリシー反映が必須**。利用前シートに送信の旨を明記済み。

## 12. 実装時の注意点（既存を壊さない）

- **DBスキーマ / マイグレーション**: 既存の旅行・商品・写真・レートのテーブルを破壊しない。**保存時レートのカラムを保持**（§10レート方針）。上限・Pro状態は新カラム/別テーブルで追加。
- **OCRパイプライン**: 基本OCRの既存処理を維持し、高性能OCRは**別関数＋回数チェック**でラップ（基本OCR失敗の文脈から呼ぶ）。送信前に同意状態を確認。
- **保存ロジック**: 候補/購入済みの状態遷移・写真（OCR写真と保存写真の区別）を既存仕様のまま。**保存件数カウント**を一元化し、上限判定はそこで。
- **旅行切り替え**: アクティブ旅行のグローバル状態を単一ソースに。分析・カレンダー・設定はそれを購読。
- **課金状態**: entitlement（Pro有無・OCR残回数）を**単一のhook/context**で配布。UIは状態を読むだけにし、購入処理は RevenueCat に委譲。
- **下タブ**: §10の通り単一の `(tabs)` を正とし、二重化しない。
- **数値の出所**: 価格はRevenueCat、上限/回数は`config`。**画面にハードコードしない**。
- **空/エラー状態**: 既存の空状態トーンに合わせる（`EmptyState`を必ず流用）。
- **アクセシビリティ/ヒット**: タップ領域44pt以上、金額は等幅数字、コントラスト確保。
